# todo 기록 형식 (log.jsonl)

- **지금 판: 1** · 읽을 수 있는 가장 낮은 판: 1 · 기계용 형식: [`log.v1.schema.json`](log.v1.schema.json) · 판 기록: [`CHANGES.md`](CHANGES.md)

할 일에 일어난 일을 한 줄에 하나씩 덧붙여 남긴다. 고치거나 지우지 않는다. 달마다 파일을 나눈다.

- 위치: `<data_dir>/<log_dir>/YYYY-MM.jsonl` (기본 `~/todo/log/2026-11.jsonl`)
- 한 줄 = JSON 객체 하나. 글자는 UTF-8.
- 장부(`list.md`)는 「지금 상태」이고, 이 기록은 「지나온 일」이다. 둘은 `task` 로 이어진다.
- 아침 브리핑은 이번 달과 지난달 파일만 읽는다. 긴 기간 질문은 나중에 이 파일들로 만든 색인(SQLite)에 묻는다.

## 모든 줄에 있는 필드

| 필드 | 형식 | 설명 |
|---|---|---|
| `v` | 숫자 | 형식 판. 지금은 `1`. 필드가 바뀌면 올린다 |
| `at` | 시각 `2026-11-02T07:00:12+09:00` | 이 일이 일어난 때. 사람이 지금 있는 곳의 시간대를 붙인다(뉴욕이면 `-05:00`, 컴퓨터 시간대가 아님) |
| `day` | 날짜 `2026-11-02` | 어느 하루에 속하나. 사람이 지금 있는 곳의 시각으로 센다. 새벽 1시 전은 전날이다(`day_boundary_hour`) |
| `kind` | 글 | 일어난 일의 종류. 아래 「종류」 표 |
| `task` | 글 `t-20261102-01` | 장부의 할 일 번호. 만든 날 + 그날 순번이라 바뀌지 않는다. 화면의 `#7` 과는 다르다 |
| `title` | 글 | 그때의 할 일 이름. 나중에 이름이 바뀌어도 그때 글을 남긴다 |
| `by` | `person` · `ai` · `program` | 누가 했나. 장부를 바꾸는 줄(`add` · `pick` · `done` · `drop`)은 `person` 만 |

## 종류(kind)와 그 종류만의 필드

| kind | 언제 | 더 붙는 필드 |
|---|---|---|
| `recommend` | 아침 원고가 이 일을 추천했을 때 | `n` · `group` · `reason` · `source` · `brief` |
| `pick` | 사람이 번호로 골랐을 때 | `n` · `answer` · `do` · `said` |
| `add` | 장부에 새 줄이 생겼을 때 | `due` · `do` · `project` · `requester` · `from` |
| `done` | 끝냈을 때 | `picked_day` · `said` |
| `drop` | 「안 함」으로 뺐을 때 | `said` |
| `wait` | 남에게 맡기고 답을 기다릴 때 | `who` · `check_on` |
| `change` | 마감 · 할 날 · 이름이 바뀌었을 때 | `field` · `before` · `after` · `said` |

| 필드 | 형식 | 설명 |
|---|---|---|
| `n` | 숫자 | 화면에 보인 번호(`#7` 이면 `7`). 답을 번호로 풀 때 쓴다. 플러그인 0.2.0부터 화면 번호 = 장부에 고정된 `#번호` 라서 날이 바뀌어도 같은 일을 가리키고, `add` · `change` · `done` 에도 붙일 수 있다(선택). 0.1.0 의 줄은 그날 화면에서만 맞는 번호다 |
| `group` | `must` · `unblock` · `quick` · `check` · `big` | 원고의 묶음. 오늘 꼭 · 막힘 풀기 · 짧게 끝낼 일 · 확인 · 큰 일정 |
| `reason` | 글 | 근거 한 줄. 화면에 쓴 그대로 |
| `source` | `calendar` · `journal` · `session` · `mail` · `ledger` · `person` | 근거를 어디서 봤나 |
| `brief` | 글 | 그날 원고 파일 이름(`days/2026-11-02.md`). 화면 전체를 다시 볼 때 |
| `answer` | `today` · `date` · `none` | 고른 답. `none` 은 무응답으로 다음 날 다시 묻는다 |
| `do` | 날짜 | 할 날. 사람이 정한 날이다 |
| `due` | 날짜 | 마감. 사실이다(캘린더 · 요청자가 정한 날) |
| `project` | 글 | 프로젝트 이름(「연말 행사」 · 「배달」) |
| `requester` | 글 | 시킨 사람. 내 일이면 비운다 |
| `from` | 글 | 이 일이 처음 나온 곳(「추천 #7」 · 「사람 말」) |
| `repeat` | 글 | (선택 · `add`) 반복 일. 「매일」 · 「매주 월」. 수강생용 플러그인 `plugins/todo` 가 쓴다. 선택 필드라 판은 그대로 1 |
| `said` | 글 | 사람이 한 말 그대로(「#7 #8 오늘」). 사람의 답이 학습 재료가 된다 |
| `sub` | 숫자 | (선택) 세부 할 일 번호. `#8-2` 면 `n:8`, `sub:2`. 0.3.0부터 |
| `parent` | 글 `t-20261124-08` | (선택) 세부 할 일의 부모 `task`. 0.3.0부터 |
| `picked_day` | 날짜 | 이 일을 골랐던 날. 「고른 날 → 끝낸 날」을 잴 때 |
| `who` · `check_on` | 글 · 날짜 | 기다리는 상대와 다시 확인할 날 |
| `field` · `before` · `after` | 글 | 바뀐 칸과 그 전후 값 |

## 넣지 않는 것

- 메일 본문 · 메일 주소 · 비밀번호 · 토큰. 메일은 「메일 10/31 알림」처럼 날짜와 종류만 적는다.
- 화면 전체 글. 원고는 `days/` 와 지식베이스에 있고, 여기는 `brief` 로 가리키기만 한다.

## 예

```jsonl
{"v":1,"at":"2026-11-02T07:00:12+09:00","day":"2026-11-02","kind":"recommend","task":"t-20261102-01","title":"견적서 보내기","by":"ai","n":7,"group":"must","reason":"장부 · 마감 2일 남음","source":"session","brief":"days/2026-11-02.md"}
{"v":1,"at":"2026-11-02T08:41:03+09:00","day":"2026-11-02","kind":"pick","task":"t-20261102-01","title":"견적서 보내기","by":"person","n":7,"answer":"today","do":"2026-11-02","said":"#7 #8 오늘 · #9 내일"}
{"v":1,"at":"2026-11-02T08:41:03+09:00","day":"2026-11-02","kind":"add","task":"t-20261102-01","title":"견적서 보내기","by":"person","due":"2026-11-13","do":"2026-11-02","project":"견적","from":"추천 #7"}
{"v":1,"at":"2026-11-02T16:20:44+09:00","day":"2026-11-02","kind":"done","task":"t-20261102-01","title":"견적서 보내기","by":"person","picked_day":"2026-11-02","said":"7 끝"}
{"v":1,"at":"2026-11-03T08:10:00+09:00","day":"2026-11-03","kind":"pick","task":"t-20261101-04","title":"연말 행사 할 일 목록 정하기","by":"person","n":9,"answer":"none","said":""}
```

## 이 기록으로 답하는 질문

| 질문 | 쓰는 줄 |
|---|---|
| 어제 고른 일 중 몇 개 끝냈나 | 어제 `pick` 의 `task` 중 `done` 이 있는 것 |
| 세 번 밀린 일 | 같은 `task` 의 `pick` 중 `answer` 가 `none` 이거나 `do` 가 계속 뒤로 간 것 |
| 추천했는데 한 번도 안 고른 일 | `recommend` 는 있고 `pick` 이 없는 `task` |
| 고른 뒤 끝내기까지 며칠 | `done` 의 `day` − `picked_day` |
| 어디서 온 추천이 잘 골라지나 | `recommend.source` 별 `pick` 비율 |
